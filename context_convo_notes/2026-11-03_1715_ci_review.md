## Corrected in this change

1. Every pull request since 15 showed a failed `pull_request` CI run on its first commit. Those runs were created by github-actions[bot] when Auto-PR opened the draft with `GITHUB_TOKEN`; GitHub gave them zero jobs and marked them failed at merge. The push run on the same commit was green each time. `ci.yml` now runs on every push only, and the main ruleset requires the `Rust check and test` check on the head commit.
2. `cargo test --all-targets` at the workspace root tested only the root crate. Both CI commands now pass `--workspace`, so `bench` is built and tested.
3. The bench bound `0.0.0.0` and ignored `PRIMNESS_DASHBOARD_HOST`. It now binds that variable, default `127.0.0.1`. The container sets `0.0.0.0` behind its `127.0.0.1` port mapping.

- `is_b_smooth` in `d1_measure` trial-divides by every integer up to B in `u64`. It is fine for the toy region and unusable at the prediction's bounds on 40–80 digit values. The real protocol needs BigInt evaluation and a sieved prime list.

- `docs/d1_falsifiable_prediction.md` step 2 and the `Next` line of `data/d1_test_instances.md` still name msieve as a polynomial source, which the 264-bit gate rules out for these instances.
