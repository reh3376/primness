# CI Principle (2026-11-03)

CI tests that spawn on new pull requests are a powerful tool to enforce consistency and surface serious errors early. They form part of the historical Dev → PR → approve/merge → confirm segmentation.

## Usage rule
- Enforce what is necessary for the current stage of the work (compilation, basic unit tests, documentation metadata presence).
- Remain dynamic: thresholds and checks evolve with the project rather than becoming brittle gates.
- Avoid unnecessary failures (overly strict linting, flaky external dependencies, or checks that do not yet apply).
- Serve the purpose of early detection and consistency without blocking legitimate progress under Obstacle D.

## Initial workflow
`.github/workflows/ci.yml` runs `cargo check` and `cargo test` on pull requests to `main` and on pushes to `primness_dev01`. It will be extended only when additional necessary checks are identified.
